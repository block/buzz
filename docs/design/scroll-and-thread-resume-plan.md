## 1. What exists today

- **The main-timeline "Jump to latest" pill already ships.** `desktop/src/features/messages/ui/MessageTimeline.tsx:862-885` renders `<UnreadPill direction="down" testId="message-scroll-to-latest">` whenever `!isAtBottom`, labelled `bufferedTimeline.pendingCount > 0 ? unreadCountLabel(...) : newMessageCount > 0 ? ... : "Jump to latest"`, onClick `setIsSemanticallyAtBottom(true)` then rAF `scrollToBottom("auto")`.
- **The thread panel hand-rolls a second, unshared pill.** `desktop/src/features/messages/ui/MessageThreadPanel.tsx:851-867` — a raw `<Button data-testid="thread-scroll-to-latest">` with a copy-pasted class string, its own inline `${n} new message(s)` label, `bottom-36`, and `scrollToBottom("smooth")`. `grep` confirms `ArrowDown` (`:2`, used only at `:861`) and `Button` (`:41`, used only at `:853`/`:865`) are its sole consumers.
- **The pill's count over-reports.** `useBufferedTimelineMessages.ts:88` returns `pendingCount = Math.max(0, messages.length - stableBuffered.length)` — a raw length diff over the full message array, which includes thread replies. `buildMainTimelineEntries` filters replies out of the rendered list (`threadPanel.ts:442-446`: `message.parentId == null || isBroadcastReply(...)`). So "5 new messages" can release zero new rows.
- **The `newMessageCount` fallback branch is dead.** Its only increment site is `useAnchoredScroll.ts:756`, gated by `!virtualizerOwnsPrependAnchoring` at `:733`, and `useTimelineVirtualizer` is a hardcoded `true` (`MessageTimeline.tsx:225`).
- **The channel read marker advances on arrival regardless of scroll position.** `useChannelOpenReadState.ts:36` calls `markChannelRead(activeChannelId, activeReadAt, { topLevelOnly: true })` in an effect keyed on `activeReadAt`, which is recomputed from the newest top-level message on every commit (`ChannelScreen.tsx:200-211`). Scroll up, take 20 arrivals, switch away → no unread dot. There is **no** `isAtBottom` gate anywhere in read state.
- **The thread's resume position already exists in memory.** `useChannelUnreadState.ts:286-306` computes `threadFirstUnreadReplyId` from `threadOpenReadSnapshotRef` (`:228-261`), a pre-mark-read per-thread freeze that correctly distinguishes captured-null from never-captured via `snapshot.has(replyId)`. It is exported at `:509` and consumed **only** to place the divider (`MessageThreadPanel.tsx:690`).
- **The thread scroll mechanism already exists and is unused for unread.** A non-null `scrollTargetId` (`ChannelPane.tsx:814`) becomes `targetMessageId` (`MessageThreadPanel.tsx:518`) and the init branch centers it instead of bottom-pinning (`useAnchoredScroll.ts:632-650`). `handleOpenThread` hard-clears it to null (`useChannelPaneHandlers.ts:217`), so every thread open bottom-pins.
- **Thread replies are fetched eagerly and completely; the panel is not virtualized.** `useThreadReplies.ts:88-104` pages the whole subtree (200/page, 500 pages); `MessageThreadPanel.tsx:680` is a plain `.map()` inside an `overflow-y-auto` body (`:559-567`). No backward-fetch machinery is needed for B.

## 2. Feature A — scroll to bottom

**Recommended approach:** the pill is shipped; the gaps are (i) a duplicated, untested thread twin, (ii) a count that lies, and (iii) arriving at the bottom marks nothing read while sitting away from it marks everything read. Ship those three. **Do not** ship a global `Cmd/Ctrl+End` binding (it steals end-of-document caret movement inside the composer) — defer the keyboard slice and scope it to editable-exempt keys only.

## 3. Feature B — thread resumes at last read

**Per-thread read state does NOT need new persistence.** The `msg:<eventId>` markers that answer "which replies were unread" are already written on thread open (`useChannelUnreadState.ts:275-281`), already persisted to `buzz.channel-read-state.v2:<pubkey>`, and already synced as kind 30078. The resume position is `threadFirstUnreadReplyId`, computed every render. **No new localStorage key, no new context-key prefix, no relay change, no new Nostr kind.**

I reject the alternative `tpos:<rootId>` local-only key proposed in thread-A: it adds a third key family for "reading a thread" (the inbox writes `thread:`, the panel writes `msg:`), it shares the same un-community-scoped 1,000-entry prunable pool (`readStateFormat.ts:16`), and it improves only a constant factor on an eviction pressure nobody has measured. Also **never** write the spec key `thread:<rootId>` from the panel — `unreadChannelCounts.ts:136-149` folds `getThreadOwnMarker(event.rootId)` into every reply's readAt, so it would mark the entire subtree read for badge purposes and publish that collapse to every device.

## 6. Risks and what will bite

1. **The mount-pin rAF race (S3).** Confirmed in source: `mountPinRafIdRef` (`useAnchoredScroll.ts:627-630`) is cancelled only by the channelId reset (`:245-247`), and the post-mount target effect (`:884-933`) centers without cancelling it. On a thread→thread switch with cached replies, `isLoading` is false while the DOM still holds the old thread's rows, so the init branch arms the rAF and the later centering can be undone. Cold mount is accidentally saved by `useDeferredValue(threadReplies, EMPTY_THREAD_REPLIES)`; the switch is not.
2. **An own-pubkey filter on the pending count breaks a listed regression.** `virtualization.spec.ts:822-831` emits with no `pubkey` — which resolves to `MOCK_IDENTITY_PUBKEY`, the logged-in identity (`e2eBridge.ts:1443`) — and asserts `toContainText("1")`. Same for a kind filter: buffered system/job rows *do* render. Thread-reply filter only.
3. **`markedChannelIdRef` set on a commit that marked nothing = a channel that never clears.** `activeReadAt` is null before `messagesQuery.data` loads (`ChannelScreen.tsx:200-211`); the mark is a no-op but the ref records the open. Only set it when the mark landed.
4. **S5 is a behavior change and will break existing specs correctly.** Any spec that leaves a channel scrolled away, takes arrivals, and asserts no unread dot after switching away now fails. Budget time to read each failure rather than tuning the gate to make them pass.
5. **The huddle transcript aliases the channel timeline.** One `MessageTimeline` mount, one `ChannelPane` mount; the transcript is a prop mode (`ChannelPane.tsx:570-575`). Without the `isHuddleTranscript` scope-off, transcript scroll position gates the channel's read marker. `useHuddleReadMarker.ts:78` remains a second ungated path.
6. **The `pinned-center` anchor is released within one commit — do not claim reflow protection.** Init calls `onTargetReached` synchronously (`useAnchoredScroll.ts:645`) → `resolveExternal` true when `layoutTargetId === null` → target nulled → `releasePinnedCenter()` at `:880-884`. Conversely, `releasePinnedCenter` does *not* scroll, so a failure to release freezes the reader in place rather than hiding new replies.
7. **Manual "Mark unread" is invisible to the resume.** `computeThreadUnreadMarker`'s 4th param `isForcedUnread` defaults to `() => false` (`unreadMarker.ts:117`) and the divider memo at `:296-305` passes only three arguments. `forcedUnreadMsgRef` reaches the badge and the row menu but not the divider — nor now the resume.
8. **Muted threads resume to the same reply forever.** The on-open mark-read is skipped for them (`useChannelUnreadState.ts:277`), so `msg:` markers never advance. Every reopen lands on the same reply — not the self-limiting behavior an unmuted thread has.
9. **The resume force-un-collapses a user-collapsed thread head.** `scrollTargetIsVisibleReply` (`MessageThreadPanel.tsx:328-336`) suppresses `isThreadHeadRepliesCollapsed` and a layout effect at `:340-344` clears `collapsedThreadHeadId`, which is component state on a panel that is not remounted per thread. Screenshot-review it.
10. **The 60-second same-second trap will void any naive spec.** The read frontier is captured at the current second and the predicate is strict `createdAt > readAt` (`unreadMarker.ts:131`). `unread-pill.spec.ts:60-87` offsets by `UNREAD_OFFSET_SECONDS = 60` with +1s staggering. **`thread-unread.spec.ts:32`'s `emitMockMessage` takes `createdAt` in an options object; `unread-pill.spec.ts` calls its own helper positionally.** Copy-pasting between them passes a number where an object is expected → `createdAt` undefined → messages land on the read side → the whole spec passes vacuously.

# Business Core S1.5 — 经营日报、周报与趋势基线

S1.5 在 S1.4 的经营事件簿之上增加时间维度：按日或周冻结完整周期的经营事实，提供
相邻周期变化和异常 SLA 趋势，并由 Business Core 在 Business Dock 内按计划生成下一份
快照。它不新增会计或法定财务能力。

## 不可变经营快照

- 唯一键为授权范围、周期类型、周期起始日和币种；首次生成后不可更新或删除。
- 日报只接受已经结束的自然日；周报必须从周一开始，并只接受已经结束的完整周。
- 快照保存销售订单、销售出库、采购订单、生成时点库存、管理经营利润和异常 SLA 指标。
- `sourceHash` 覆盖周期、币种、授权范围和完整指标；重复请求返回既有快照，不重写历史。
- 库存与缺货数明确标记为生成时点值，金额不跨币种合并。

## 趋势与 SLA

`GET /v1/operations/trends` 和浏览器同名路径按日/周返回最多 60 份快照。每份快照与前一
周期比较销售额、出库收入、采购额、经营利润和 SLA 超时数；前一周期为零时变化率保持
空值，不制造无穷大或误导性百分比。

异常 SLA 统计同一授权范围内的新增、解决、超时数量与平均解决小时。异常条件和处置
状态仍以 S1.4 事件簿为权威，趋势只读取，不改写事件。

## Business Dock 站内订阅

- `management_report:manage_subscriptions` 是独立写权限；查看仍使用
  `management_report:read`，生成快照仍要求 `management_report:generate_snapshot`。
- 订阅保存日/周、币种、固定 UTC 偏移和本地送达小时；当前界面默认 08:00。
- worker 每分钟领取到期计划，使用原子 claim 防止多个实例重复执行；成功或失败均写入
  追加式订阅事件，下一次运行不会因失败形成紧密重试。
- 订阅只在 Business Dock 内生成快照，不发送邮件、消息或外部 webhook。

## API 与深链

| Path | Purpose |
| --- | --- |
| `GET /v1/operations/trends` | 服务身份读取日/周趋势 |
| `POST /v1/operations/snapshots` | 冻结一个完整经营周期 |
| `GET/POST /v1/operations/subscriptions` | 查看或保存站内计划 |
| `POST /v1/operations/subscriptions/{id}/commands` | 暂停或恢复计划 |
| `/api/v1/...` | 对应 BusinessSession 浏览器路径 |
| `biz://operating-trends` | Business Dock 单例入口 |

所有写入要求 `Idempotency-Key`，订阅命令要求 `expectedVersion`。快照、订阅变更及后台
结果均保留 trace 与追加式审计证据。

## 明确排除

不包含凭证、总账、银行、发票、税务、法定利润、法定财务报表、预算会计或外部报表
分发。经营利润继续沿用 B4 的管理口径。

# Business Core S1.3 — 经营报表稳定性与可观测性

S1.3 不扩展财务域。它让 S1 经营驾驶舱和数据质量中心能够回答三个运营问题：

1. 这次读取是否按目标完成，如何用 trace id 定位？
2. 数据是否新鲜，是否存在积压、失败或对账差异？
3. 如果变慢，最慢的是权限、销售、采购、库存、利润还是投影阶段？

## 读取契约

`GET /v1/operations/dashboard` 与浏览器对应路径新增：

- `reportHealth`：`complete | partial | blocked`、投影新鲜度、积压、失败和结构化告警；
- `diagnostics`：总耗时、目标、最慢阶段和各阶段耗时；
- `run`：trace id、完成状态、服务端耗时、目标和完成时间。

`GET /v1/operations/data-quality` 保留四域对账结果，并新增：

- 投影新鲜度秒数和阈值；
- 结构化 `alerts`；
- 同样的 `diagnostics` 与 `run`。

所有字段继续应用 `management_report:read` 和 B1 数据范围。诊断只暴露稳定的阶段名、
耗时和 trace id，不返回 SQL、绑定参数、凭据或数据库对象标识。

## 告警优先级

| Code | Severity | Meaning |
| --- | --- | --- |
| `RECONCILIATION_DIFFERENCE` | critical | 权威业务事实与投影存在差异 |
| `PROJECTION_FAILURE` | critical | 利润投影存在失败待处理 |
| `PROJECTION_BACKLOG` | warning | 已有事件尚未完成投影 |
| `PROJECTION_WORKER_DISABLED` | warning | 投影 worker 未启用 |
| `PROJECTION_STALE` | warning | 投影水位超过新鲜度阈值 |
| `SLOW_REPORT_READ` | warning | 当前读取超过路由目标 |

`critical` 阻断经营结论；`warning` 要求标记部分可用或调查性能，但不授权直接修改事实。

## 性能与索引

- 经营驾驶舱目标：500ms。
- 数据质量管理聚合目标：2s。
- 月份过滤使用 `[month_start, next_month_start)` 日期范围，不对日期列调用 `to_char`。
- S1.3 migration 为销售订单、出库、采购订单/行、利润事实、投影失败和利润 outbox
  增加经营读取索引。

索引只服务销售、采购、库存和管理利润经营读取，不创建会计账簿、凭证、发票或税务模型。

## UI

驾驶舱和数据质量中心顶部提供一条经营仪表读数：整体状态、数据新鲜度、本次耗时、
最慢阶段和短 trace id。异常以 warning/critical 证据条展示；无异常时明确显示
`NO ACTIVE ALERTS`，避免把空白误解为未加载。

# Business Core S1 — 核心稳固与经营驾驶舱

S1 不新增财务域。它在 B1–B4 的权威业务事实之上统一提供稳定性状态、
跨域对账和经营驾驶舱，将“功能闭环”推进为“可持续运营的业务核心”。

## 范围

- 销售、采购、库存和管理利润的单币种经营驾驶舱。
- 库存、经营应收、经营应付、利润投影的范围内对账汇总。
- 利润投影 worker 水位、积压和失败状态。
- BusinessSession 浏览器读取、服务身份读取和只读 MCP 工具。
- Business Dock 的 `biz://operations-dashboard` 与 `biz://data-quality`。
- 不可变经营日报/周报、相邻周期趋势、异常 SLA 趋势与 Business Dock 站内订阅。

明确不包含电子发票、银行流水、会计凭证、总账、税务、法定利润和法定报表。

## 经营指标原则

- 金额只在同一币种内合计，绝不隐式换汇。
- 销售履约率按订单计数，不混合商品数量。
- 采购到货率按采购行完成数计数，不跨 SKU/UOM 汇总数量。
- 库存数量不跨 SKU/UOM 汇总；驾驶舱展示库位商品计数和单币种库存价值。
- 利润继续使用 B4 不可变利润事实和来源水位，保持非财务法定口径警告。

## 读取面

| Path | Purpose |
| --- | --- |
| `GET /v1/operations/dashboard` | 服务身份下的范围内经营驾驶舱 |
| `GET /v1/operations/data-quality` | 服务身份下的四域数据质量状态 |
| `GET /api/v1/operations/dashboard` | BusinessSession 经营驾驶舱 |
| `GET /api/v1/operations/data-quality` | BusinessSession 数据质量中心 |

两条读取都要求当前用户拥有 `management_report:read`，并再次应用 B1 的法律主体、
仓库、客户、供应商、品牌和业务单元范围。精确对象和差异详情继续通过各域已有的
对账端点下钻。

## 数据质量状态

- `complete`：四域无差异、无待处理投影失败、无积压且 worker 水位新鲜。
- `partial`：没有权威差异，但 worker 未启用、水位过期或仍有待消费事件。
- `blocked`：存在对账差异或待处理投影失败。

恢复必须先检查证据，再运行范围内对账或幂等投影重放。禁止直接更新事实、事件、
分配或报告快照表。

## 验证

```bash
. ./bin/activate-hermit
just business-s1-check

BUSINESS_CORE_B4_TEST_DATABASE_URL='postgres://.../disposable_s1' \
  cargo test -p business-core --test postgres_b4 -- --nocapture
```

PostgreSQL 流程同时验证销售出库、成本快照、利润投影、分配、冲销、快照、经营
驾驶舱、投影水位和四域一致性。

## S1.3 可观测性扩展

S1.3 为两条经营读取增加 traceable run、分阶段耗时、最慢阶段、数据新鲜度和结构化
告警，并将月份过滤改为可使用索引的日期范围。契约、告警优先级和索引边界见
[S1.3.md](S1.3.md)。

## S1.4 经营异常处置闭环

S1.4 将结构化告警持久化为按数据范围隔离的经营事件，增加负责人、确认、处理中、
处理时限、解决门槛和追加式审计轨迹。底层条件必须经重新扫描确认清除后才能解决；
完整契约见 [S1.4.md](S1.4.md)。

## S1.5 经营日报、周报与趋势

S1.5 冻结完整日/周经营周期，比较销售、采购、真实利润和异常 SLA，并允许在 Business
Dock 内按计划生成下一份快照。快照不可变，订阅有独立权限和审计；完整契约见
[S1.5.md](S1.5.md)。

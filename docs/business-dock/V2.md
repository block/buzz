# Business Dock V2

V2 在 V1 的同一个 iframe、Provider、Dock 布局和 CSP 基础上增加业务资源导航联动，不改变 Buzz 的频道、消息、Agent Runtime、Relay 或 Nostr Event 模型。

## BusinessResource

统一资源结构位于 `desktop/src/features/business-dock/businessResourceResolver.ts`：

```ts
type BusinessResource = {
  version: 1;
  type: BusinessResourceType;
  id?: string;
  path: string;
  title?: string;
  legalEntityId?: string;
  period?: string;
  metadata?: Record<string, string>;
};
```

Resolver 集中维护销售订单、采购订单、客户、供应商、库存、应收、应付、发票、付款和管理报表路径。它接受配置 Origin 下的 HTTPS URL、allowlist 中的 `biz://` 引用或已经验证的结构化对象，最终只输出相对业务路径。

首选消息引用示例：

```md
[查看订单 SO-001](biz://sales-order/SO-001)
```

普通左键在当前 Buzz 内展开 Dock 并导航；Cmd/Ctrl + Click 使用系统浏览器。已有链接右键菜单对业务资源显示 Open in Business Dock、Open in Browser 和 Copy Link。

## Bridge V2

V2 信封：

```ts
type BusinessBridgeEnvelope<T = unknown> = {
  version: 2;
  type: string;
  requestId: string;
  sessionNonce: string;
  payload?: T;
};
```

Host → Business：

- `HOST_INIT`
- `SET_THEME`
- `REFRESH`
- `NAVIGATE`，payload 为 `{ resource: BusinessResource }`
- `SET_CONTEXT`，首版只允许 `legalEntityId` 和 `period`
- `REQUEST_CURRENT_RESOURCE`

Business → Host：

- `BUSINESS_READY`
- `TITLE_CHANGED`
- `ROUTE_CHANGED`
- `RESOURCE_CHANGED`
- `ACTION_COMPLETED`
- `ACTION_FAILED`
- `DATA_CHANGED`
- `DIRTY_STATE_CHANGED`

Host 为当前 iframe 会话生成随机 nonce。V2 入站消息必须同时通过精确 `event.origin`、`event.source`、版本、类型、requestId、nonce 与 payload schema 校验。V1 的 Ready、Title 和 Route 消息仍可解析；未实现 Bridge 的页面继续通过受控 iframe `src` 导航。

`ACTION_COMPLETED` / `ACTION_FAILED` 只更新 Dock 状态并显示 Toast，不产生 Buzz 消息或 Agent 动作。失败事件只显示经过长度约束的 message，原始 stack 不进入宿主状态。`DATA_CHANGED` 发出 `buzz:business-data-changed` DOM 事件，detail 只含资源类型和可选 ID。

## 导航和本地状态

- 宿主历史存储 `BusinessResource[]` 和 index；新资源截断 forward history，相同 path 去重，iframe route/resource 回传替换当前项。
- `followConversation` 默认 true，`pinned` 默认 false，保存在 `buzz.business-dock.preferences.v2`。
- pinned 阻止预留的后台自动导航，但用户显式点击始终可导航。
- pending navigation 只保留最新资源，Bridge Ready 后补发。
- Toolbar 显示资源类型与 ID，并提供 Follow、Pin、Fullscreen、Open External、Copy Business Reference 和 Close。

## 未保存保护

收到 `DIRTY_STATE_CHANGED { dirty: true }` 后，关闭 Dock、切换资源、Home、Back、Forward、外部打开和退出 Fullscreen 都先显示 Buzz 原生 AlertDialog。应用 WebView 的 `beforeunload` 也会请求系统级离开确认。

## 开发 Mock 与验证

`business-dock-test.html` 支持 V2 握手和全部入站事件，并提供 Change Resource、Mark Dirty/Clean、Action Success/Failed、Data Changed 按钮。

```bash
cd desktop
node --import ./test-loader.mjs --experimental-strip-types --test 'src/features/business-dock/*.test.mjs'
pnpm build:e2e
pnpm playwright test --project=smoke tests/e2e/business-dock.spec.ts
```

## V2 范围边界

本版只实现 Markdown 业务链接，不增加 Business Resource Block，也不修改 Composer Draft API。没有 SSO、token 交换、财务权限、业务模块、数据库、MCP 执行工具、自动审批、Relay 修改或新 Nostr Kind。

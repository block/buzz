Buzz Relay — Build Architecture

One Dockerfile assembles two independent build tracks into a single runtime image

Rust binaries (buzz-relay, buzz-admin, buzz-pair-relay) and the web bundle (pnpm + vite) build in parallel, then converge into a debian-slim runtime published as ghcr.io/block/buzz.

1
Dependency layer caching cuts rebuild time
recipe.json is derived from manifests alone, so the builder re-cooks dependencies only when Cargo.toml or Cargo.lock changes — not on every source edit.
2
Web build cannot invalidate the Rust cache
pnpm/vite run as a fully independent stage, so a front-end change never busts the cached Rust dependency layers, and vice versa.
3
Debug and production binaries cannot drift
runtime-debug and runtime strip the same optimized ELF output, so profiler-visible code and shipped code are generated identically.
